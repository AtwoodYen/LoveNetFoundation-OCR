# 捐獻袋 OCR 15 階段處理規則

本文件記錄捐獻袋 OCR 辨識的 15 階段處理規則。

---

## 第一階段：過濾無效資料

### 目的
過濾雜訊、重複標記等無效資料，並記錄信封上緣 Y 值。

### 規則

#### 規則 1：過濾「項目」和「金額」標題
- 文字內容為「項目」或「金額」的區塊不放入最終輸出
- 記錄這些區塊的 Y 軸值作為信封上緣 (envelope_top_y)

#### 規則 2：過濾長度=4 且有 3 個圓形字元的區塊
- 搜尋範圍：index < 20 的區塊
- 圓形字元：○, o, O, 〇（不含數字 "0"）
- 純數字金額（如 3000, 1000）不過濾

#### 規則 3：過濾長度=4 且有 3 個相同字元的區塊
- 搜尋範圍：index < 20 的區塊
- 例如：Q000, ooov, ○○○v
- 純數字金額不過濾

#### 規則 4：連續 4 筆中有 3 筆相同
- 搜尋範圍：index < 20 的區塊
- 連續 4 筆資料中有 3 筆內容相同時，這 4 筆都過濾

#### 規則 5：長度=3 且 3 個字元相同，檢查相鄰區塊
- 搜尋範圍：index < 20 的區塊
- 觸發條件：找到長度為 3 且 3 個字元內容都相同的資料（如 "000"、"ooo"）
- 檢查 index-1 和 index+1 的兩筆資料：
  - **條件 A**：有長度為 1 的資料，且內容是特殊符號、英文大寫、或數字
  - **條件 B**：兩者 X 軸差距 < 30px
- 若符合任一條件，則這 2 筆資料（長度3的和相鄰的）都過濾
- 被規則 5 過濾的區塊不會被當作勾選標記

---

## 第二階段：組合捐獻項目並配對金額

### 目的
找出四個捐獻項目的關鍵字，組合名稱，並配對金額。

### 四個捐獻項目

| 項目名稱 | 關鍵字 |
|----------|--------|
| 課程推廣與發展 | 課程, 推廣, 與, 發展 |
| 媒體製作與傳播 | 媒體, 製作, 與, 傳播 |
| 基金會營運支持 | 基金會, 營運, 支持 |
| 其他 | 其他 |

### 處理步驟

#### 2.1 尋找捐獻項目關鍵字
1. 先找出非共用關鍵字（如「課程」「推廣」「發展」），建立基準 Y 值
2. 對於共用關鍵字「與」，選擇 Y 值最接近基準 Y 值的區塊
3. 計算各項目的 Y 軸平均值 (avg_y)，儲存於 temp.json 的 `Donate No.Donate Item-X.avg_y`

#### 2.2 尋找捐獻金額
- 從過濾後的區塊中尋找第一個有效數字
- 跳過 4 位以上全為 0 的字串（如 "0000"，視為佔位符）
- "0" 本身是有效金額（表示零元）
- 儲存於 temp.json 的 `Donate No.Donate_Money`

#### 2.3 配對金額與捐獻項目
- 將金額的 Y 軸與四個捐獻項目的 Y 軸平均值比較
- **Y 軸距離最近的項目就是被勾選的項目**
- 輸出格式：`項目名稱：金額`（如 `其他：100`）

---

## 第三階段：找出合計金額

### 處理步驟
1. 尋找「合計」標籤，記錄其 Y 軸值 (heji_y) 和 index (heji_index)
2. 從捐獻金額的 index 之後，尋找與捐獻金額相同且與「合計」Y 軸距離 < 40px 的資料
3. 若未找到符合條件的，使用捐獻金額作為合計

---

## 第四階段：過濾公告聲明

### 目的
過濾法律聲明文字（財團法人法第 25 條相關說明），不輸出這些內容。

### 公告關鍵字序列
```
依, 《, 財團, 法人, 法, 》, 第, 25, 條, 規定, ,, 本, 會, 需, 主動, 公開, 捐款, 者, 資訊, ;,
倘若, 您, 希望, 保密, 捐款, 資訊, ,, 請, 勾選, 「, 捐款, 不, 公開, 聲明, 」, 提供, 聲明, 書, 之,
捐款, 人, ,, 將, 依法, 規定, 公開, 揭露, 捐款, 者, 姓名
```

### 處理步驟
1. 從「合計」之後開始尋找公告聲明起始點（「依」或「《」或「財團」或「法人」）
2. 持續標記直到找到「姓名」
3. 從 filtered_blocks 中移除公告內容

---

## 第五階段：不同意揭露聲明

### 關鍵字序列
```
本人, 在, 此, 聲明, 表示, 不, 同意, 將, 本人, 捐款, 姓名, 公開, 揭露
```

### 組合結果
- 組合文字：「本人在此聲明表示不同意將本人捐款姓名公開揭露。」
- 記錄第一個「本人」的 index 和 Y 軸平均值

### 不需要奉獻收據
- 關鍵字：`不需要, 奉獻, 收據`
- 組合文字：「不需要奉獻收據」

---

## 第六階段：收據選項

### 三種收據選項

| 選項 | 關鍵字 |
|------|--------|
| 代上傳國稅局無紙本 | 代, 上傳, 國稅局, 無, 紙, 本 |
| 電子收據 | 電子, 收據 |
| 年度紙本收據 | 年度, 紙, 本, 收據 |

### 勾選檢查
- 使用座標範圍搜尋勾選標記
- 勾選標記應在選項文字的右邊（較高的 X 值）
- Y 距離 < 100px，X 距離 < 500px

### 不同意揭露勾選檢查
- 條件：任一收據選項被勾選時
- 檢查「本人」前一個區塊是否為勾選標記

### 輸出規則
- 三種收據選項互斥，只輸出一個
- 優先順序：紙本收據 > 電子收據 > IRS
- 若都沒勾選，輸出「不需要奉獻收據」

---

## 第七階段：身分證字號

### 標籤關鍵字
```
身分, 證, 字號, :
```

### 格式驗證
- 長度：10 碼
- 格式：1 個英文字母 + 9 個數字

### 處理步驟
1. 找到標籤後，取下一個 index 的內容
2. 驗證是否符合身分證字號格式

---

## 第八階段：奉獻者姓名

### 標籤關鍵字（必須連續）
```
奉獻, 者, 姓名, :
```

### 處理步驟

#### 方法一：往前找（優先）
1. 從「奉獻」的前一個 index 開始往前找
2. 跳過長度=10 的字串（包括 "0000000000" 和身分證字號格式）
3. 遇到「:」停止
4. 合併停止點的下一個 index 到「奉獻」前一個 index 的內容

#### 方法二：往後找（備用）
1. 從「:」的下一個 index 開始往後找
2. 遇到下一個「奉獻」停止（不加入）

---

## 第九階段：奉獻日期

### 標籤關鍵字
```
奉獻, 日期, :
```

### 日期標記
```
年, 月, 日
```

### 處理步驟
1. 從「:」的下一個 index 開始往後找
2. 收集數字和日期標記（年、月、日）
3. 支援斜線日期格式（如 115/7/29）
4. 找到完整的年月日後停止

### 組合格式
- `2016年12月8日`
- `115年7月29日`

---

## 第十階段：奉獻收據抬頭

### 標籤關鍵字（必須連續）
```
奉獻, 收據, 抬頭, :
```
合併成「奉獻收據抬頭:」，暫存於 temp.json 中（命名為 `title`）

### 處理步驟
抬頭的文字不外乎在「奉獻」前方，或在「:」後方。找抬頭的技巧與第八階段找姓名相同。
**前後都要找，找到的結果合併輸出。**

#### 往前找
1. 從「奉獻」的前一個 index 開始往前找
2. 遇到「:」或「日」停止（「日」不加入抬頭）
3. 合併停止點的下一個 index 到「奉獻」前一個 index 的內容
4. 跳過數字字串（抬頭不含數字）

#### 往後找
1. 從「:」的下一個 index 開始往後找
2. 遇到下一個「奉獻」停止（「奉獻」不加入抬頭）
3. 跳過數字字串

### 輸出規則
當 `title` 有內容時，輸出「奉獻收據抬頭:」+ temp.json 中 `title` 的內容

---

## 第十一階段：奉獻收據寄送地址

### 標籤關鍵字（必須連續）
```
奉獻, 收據, 寄送, 地址, :
```

### 處理步驟
1. 從「:」的下一個 index 開始往後找
2. 遇到「聯絡」停止（不加入）
3. **過濾規則**：地址開頭如果是 6 字元且有 5 個以上 "0"，則忽略（如 "000000"、"⑦00000"）

---

## 第十二階段：聯絡電話

### 標籤關鍵字
```
聯絡, 電話, :
```

### 電話格式
- 只能由數字和「-」組成

### 輸出規則
- 電話號碼長度 > 8 才輸出

---

## 第十三階段：電子信箱

### 標籤關鍵字
```
電子, 信箱, :
```

### Email 格式驗證
- 必須包含「@」符號
- 只能由 ASCII 可見字元組成（字元碼 33-126）
- 「@」不能在開頭或結尾

---

## 第十四階段：修正重複冒號

### 目的
修正輸出文字中的重複冒號問題。

### 處理步驟
1. 檢查所有輸出行
2. 將連續的冒號（如「::」）修正為單一冒號（「:」）

---

## 第十五階段：線上奉獻過濾

### 目的
過濾輸出結果中與「線上奉獻」相關的行。

### 處理規則
1. 檢查輸出結果的**最後兩筆**
2. 如果任一行包含「線上」或「奉獻」字樣，該行不加入輸出
3. 此過濾適用於防止線上奉獻相關說明文字出現在最終結果中

---

## 輸出規則

### 輸出項目（共 11 項）

| # | 項目 | 輸出條件 |
|---|------|----------|
| 1 | 捐獻項目和金額 | 有配對成功的項目和金額 |
| 2 | 合計金額 | 有找到合計金額 |
| 3 | 收據選項 | 有勾選的收據選項，或「不需要奉獻收據」 |
| 4 | 不同意揭露聲明 | 有勾選不同意揭露 |
| 5 | 身分證字號 | 有找到有效的身分證字號 |
| 6 | 奉獻者姓名 | 有找到姓名 |
| 7 | 奉獻日期 | 有找到日期 |
| 8 | 奉獻收據抬頭 | 有找到抬頭 |
| 9 | 奉獻收據寄送地址 | 有找到地址 |
| 10 | 聯絡電話 | 有找到且長度 > 8 |
| 11 | 電子信箱 | 有找到有效的 Email |

### 日誌格式
- **O:** 成功辨識並輸出的項目
- **X:** 未找到或不符合條件而排除的項目（附帶原因）

---

## 座標系統說明

根據 Vision.json 的座標互換：
- **x 座標**：實際代表垂直位置（數值越大越靠下）
- **y 座標**：實際代表水平位置（數值越大越靠左，RTL 閱讀順序）

---

## 輸出文件

每個任務處理完成後，會在任務目錄下生成：

1. **Process.md** - 處理流程記錄
   - 各階段的處理統計
   - 找到的關鍵字和座標
   - 勾選狀態

2. **output.md** - 辨識結果輸出
   - 最終辨識結果文字
   - 各項目的 O/X 狀態

3. **Vision.json** - OCR 原始區塊資料

4. **temp.json** - 結構化資料（donate_no）

5. **result.json** - 完整處理結果
